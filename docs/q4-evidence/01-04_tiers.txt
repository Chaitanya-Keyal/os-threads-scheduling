## Children inherit their user's tier (sched_fork hook)
# root: tier set alice gold
# alice: renice -n 10 -p $$; sleep 3 & ps -o pid,ni,comm -p $$,$!
    PID  NI COMMAND
   2104  10 bash
   2106  -7 sleep
The parent shell was reniced to 10, but its new child starts at GOLD's -7.

## Why the workloads must share a scheduling group
# Same test with alice and bob each logged in over ssh (separate sessions):
# tier set alice gold
user alice (uid 1001) -> gold
   3864 alice     13  -7    6116   1656   1656 R  49.5   0.0   0:04.51 yes
# cgroups: alice 0::/user.slice/user-1001.slice/session-42.scope
#          bob   0::/user.slice/user-1002.slice/session-41.scope
NI is -7 but the share stays ~50%: the cpu controller gives each user slice an
equal weight, and nice values only compete inside one group.
